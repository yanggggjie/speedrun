# TabBot 设计

> 人和 agent 共用同一个 Chrome。人可以做，agent 也可以做；agent 做的时候人可随时插手，agent 能知道人做了什么。
> 原则：整体简单，关键处做扎实。agent 擅长搜索和读文本，所以给它充足、干净的数据，不替它做摘要和判断。
> 运行时架构见 `skills/tabbot/ARCHITECTURE.md`。

## 1. 场景

| 方向 | 场景 | 靠什么解决 |
|---|---|---|
| 人到 agent | 人做到一半交给 agent；人演示一遍，agent 重复 | 日志里有人的完整操作流和页面的请求；agent 自己读日志、重放请求 |
| agent 到人 | 验证码、登录、支付确认，agent 请人帮忙 | `release --reason` 加 `wait` |
| 人抢占 agent | 人看到不对，直接上手做完 | 租约一撤销 agent 就停；agent 读日志判断是否已完成 |
| 并行 | 人和 agent 在不同 tab；无人值守；事后审计 | 常驻录制 |
| 异常 | 人关了 tab、登录过期、扩展重载 | 状态自愈；丢了租约要明确告诉 agent，不静默重连 |

## 2. 关键原则

- **所有逻辑和数据在 holder，扩展、relay、CLI 只做 I/O。** 扩展的安装、重启、分发都不方便；holder 和 CLI 随 `~/.tabbot/src` 更新。扩展是固定 ABI 的管道，页面脚本由 holder 经 `chrome.userScripts` 下发。
- **录制与执行解耦。** 录制如实反映浏览器状态，无论是谁造成的；执行只管执行，不写日志。两者之间没有共享状态。
- **判人只看 `isTrusted`。** agent 的动作全是页面里的 DOM 事件（`dispatchEvent`、原生 setter），`isTrusted` 一定为假；`isTrusted` 为真就是人。不用 `chrome.debugger`，所以不弹"正在调试此浏览器"横幅。代价：个别站点不认 DOM 事件（文件选择框、部分风控、iframe 里的元素），`act` 冻结为兜底，不为个别站点加兼容代码。
- **请求优先，而且从读录制开始。** 每个任务先 `context`（用户最近做了什么）、`api`（站点有哪些接口、哪个用户操作触发它），能直接拿到数据或完成动作的接口就 `replay`，不去点页面——速度快、灵活，也让 agent 知道上下文。被拒（401/403、签名类参数、原始内容已丢失）或用户从没做过这件事，才降级到 `act`，触发一次之后接口就录到了。
- **原始请求的 token 真值可以进 holder，但只在内存里，绝不落盘。** 日志里是别名；`replay --set` 里可以写别名，由 holder 在内存里换回真值，agent 拿不到真值。
- **日志是按大小滚动的队列，和时间无关**：50MB 一段，总共 500MB，写满整段删除最旧的。
- **先把产品做好**：不为敏感内容做额外保护（默认录所有 http/https 站点，没有排除列表；HTML 文档原样存；脱敏只做最简单的）。

## 3. 录制

- **录什么**：HTML 文档（渲染后的 DOM，不是服务器原始源码）、XHR、fetch 的请求和响应（响应体不设策略上限）；人的点击、输入长度（不记内容）、特殊键、滚动；导航；页面快照。不录 WebSocket、`sendBeacon`、Worker 里的请求。后台页面只记导航和请求计数。
- **来源**：`human`（`isTrusted` 为真）、`page`（页面里的脚本触发的事件，包括 agent 的 DOM 事件，以及所有请求、导航、HTML）、`agent`（agent 的命令记录和重放，说明 agent 做了什么）。
- **过滤**：adblock 规则加第一方埋点的启发式（只对非 GET），噪声默认隐藏；同一个请求 5 分钟内重复只计数；人的事件或 agent 命令之后 2 秒内的请求记为它引发的（`cause`）。
- **日志不隐藏任何一类**，如实显示。

## 4. 控制权：租约

- 租约只管 agent **能不能写**，状态在 holder 里。页面把来源为 `human` 的事件立即上报，租约立即撤销（点击、任意按键、输入；滚轮和滚动只当"人在场"，不撤销，因为 agent 用元素引用定位，滚动不会让目标失效）；动作等页面稳定的时候真人动手，页面端立刻停止等待，告诉 holder。
- 观察通道不受租约影响：人动手后 agent 仍能读日志。
- 获取租约（`takeover`）要求人静默超过 1.5 秒，否则被拒；人接手后 agent 不能自动恢复：先读日志，再重新 `takeover`。不重试被打断的动作。租约 10 分钟没有动作自动失效；租约按标签页隔离。
- 写操作（下单、删除、发送、支付）：skill 里要求 agent 先问用户，目前没有机制强制。

## 5. agent 怎么感知

- **日志就是感知**：`tabbot log --src human --since <游标>`；每个命令的输出第一行给结论和下次的游标。
- **`wait`（前台阻塞）**：轮询日志，等人动手并静默 N 秒，或超时返回"无变化"。不依赖 harness 有没有后台通知。
- **做一半被人做完了**：agent 读日志里人的步骤和触发的请求，自己判断目标是否已达成；不登记目标，不做达成判断器。
- **显式交还优先**：人点"交还"（可附一句话）是首选信号，静默时长只是兜底。

## 6. 命令

见 `skills/tabbot/SKILL.md`：先恢复上下文 `context`、`api`；观察 `tabs`、`log`、`sql`、`snapshot`、`text`、`wait`、`status`；请求优先 `req find`、`req show`、`replay`；在原页面上操作 `takeover`、`release`、`act click|fill|select|check|press|scroll|goto`。元素用稳定引用 `@e12`（来自 `snapshot`，页面不刷新就不变，元素被移除后失效）；每个 `act` 自带等页面稳定，返回这一步引起的变化。输出是文本，第一行是结论，失败退出码非零。
