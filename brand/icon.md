# speedrun 图标

| 文件 | 作用 |
|---|---|
| [`icon.py`](icon.py) | **源文件**：所有参数都在里面，只用 python3 标准库 |
| [`icon.svg`](icon.svg) | 由 `icon.py` 生成并提交，不要手改 |
| [`make-icons.mjs`](make-icons.mjs) | 一条命令：先跑 `icon.py` 生成 SVG，再用无头 Chrome 出 `skills/spr/src/chrome-extension/icons/` 下 16、32、48、128 四个 PNG |

```bash
node brand/make-icons.mjs
```

## 一句话

**整个图标面就是一个 S。** 一条白色曲线从左边缘进、右边缘出，把整面切成红、墨两块；S 是两块颜色交界处的留白。

## 设计原则

做法沿用 yodo 的图标：

1. **整体即符号。** 没有「底板加图案」的分层。S 的两端出血（坐标超出 0 到 128），所以看起来是整面被切开，而不是一个图形摆在中间。
2. **用名字做形状。** S 来自 speedrun，不借光标、箭头、浏览器窗口这类通用符号。
3. **最像 S。** S 关于画布中心 `(64, 64)` 中心对称，转 180° 和自己重合，这是字母 S 本身的特征；两端都水平出血，不往上冲。
4. **非常流畅。** 整条 S 是一条均匀三次 B 样条，曲率连续（C2）：不只方向连续，弯的急缓也连续变化，看不出任何接缝。几段贝塞尔拼接只能做到方向连续，接点处急缓会跳一下。
5. **最小尺寸优先。** 先在 16 像素下判断，再看 128 像素。

## 构成与规格

画布 `128 × 128`，圆角矩形 `rx = 30`，四角透明，内容用 `clipPath` 裁到圆角里。

### S 的中心线

只写上半段的 5 个控制点，加上中心点，另一半由中心对称得到（`(x, y) → (128 − x, 128 − y)`），一共 11 个控制点：

| 序号 | 控制点 | 含义 |
|---|---|---|
| 0 | `(-90, 104)` | 底边，画布外 |
| 1 | `(-40, 104)` | 底边，画布外；B 样条从这里附近开始，所以线从左边缘外进来 |
| 2 | `(10, 104)` | 底边，画布内 |
| 3 | `BOWL_IN = (86, 108)` | 下弯起弯处；比底边低 4，使底边进弯时略微下沉再翻上去 |
| 4 | `BOWL_OUT = (116, 72)` | 下弯最外侧；`x` 决定弯有多宽，`y` 决定中间那一横有多斜 |
| 5 | `CENTER = (64, 64)` | 中心，S 中间那一横经过这里 |
| 6 到 10 | 0 到 4 的中心对称点 | `(12, 56)`、`(42, 20)`、`(118, 24)`、`(168, 24)`、`(218, 24)` |

- 底边高度 `TERMINAL_Y = 104`，顶边对称在 `24`。
- 均匀三次 B 样条每 4 个相邻控制点换成一段三次贝塞尔（`b0 = (p0 + 4p1 + p2)/6`、`b1 = (2p1 + p2)/3`、`b2 = (p1 + 2p2)/3`、`b3 = (p1 + 4p2 + p3)/6`），11 个控制点得到 8 段，起点 `(-40, 104)`、终点 `(168, 24)`，都在画布外。
- B 样条不经过控制点，曲线会往内收：下弯实际最右只到 `x ≈ 103`。

### 白线

| 参数 | 值 | 说明 |
|---|---|---|
| `STROKE` | `25` | 约占画布 20%，16 像素下约 3 像素宽 |
| 颜色 | `#FFFFFF` | |
| 端点 | 圆头 | 两端都在画布外，实际看不到 |

### 两块颜色

左上区域的边界就是 S 的中心线：沿 S 从左外侧走到右外侧，再经 `(200, -60)`、`(-60, -60)` 绕回，闭合。右下区域是画布底色。白线盖在边界上，所以线和色块永远对得上。

| 区域 | 渐变 | 渐变向量 `(x1, y1) → (x2, y2)` |
|---|---|---|
| 左上 `RED`（赛车红） | `#FF3B30` → `#D7001A` | `(10, 0) → (90, 90)` |
| 右下 `INK`（墨黑） | `#0B0B0E` → `#26262C` | `(128, 60) → (40, 128)` |

渐变坐标写在画布坐标系里（`userSpaceOnUse`），不随区域形状变化。绘制顺序：墨黑底色 → 红色区域 → 白线。

## 品牌色

| 名称 | 值 | 用在哪里 |
|---|---|---|
| 赛车红 | `#FF3B30 → #D7001A` | 主强调色，一个画面里只用一处，最多两处 |
| 墨黑 | `#0B0B0E → #26262C` | 深色背景；浅色背景上的文字 |
| 白 | `#FFFFFF` | 深色背景上的文字 |

选红黑的理由：白线在红、黑两块上都最清楚，16 像素下最醒目；红黑像赛车和计时，和 speedrun 贴；和 yodo 的橙红、靛紫、金完全分得开。

## 迭代记录

| 阶段 | 做法 | 结果 |
|---|---|---|
| 一 | 浏览器窗口加光标（旧图标） | 只说了「在浏览器里」，和同类工具分不开 |
| 二 | 弯路加直线箭头、s 加箭头，放在圆角底块上 | 有含义，但是「底板加图案」，不够整体 |
| 三 | 按 yodo 的做法，白线把整面切成两块，顶部上扬冲出右上角 | 不够像 S，线不够粗 |
| 四 | 标准 S 字形，线宽 22 到 28 | 像 S 了，但顶部上扬不要 |
| 五 | 中心对称，两端水平出血 | 最像 S，但几段贝塞尔拼接，不够流畅 |
| 六 | 整条 S 换成均匀三次 B 样条，弯更宽、中横更平（本版本） | 最终 |

配色比较过十套：橙红·墨紫、橙红·金、金·墨、青柠·墨、电光蓝·墨、玫红·靛蓝、珊瑚·青绿、赛车红·黑、紫·粉、双橙。金、青柠、粉这类浅色上白线不够清楚；墨紫、玫红·靛蓝和 yodo 太像；蓝色在工具栏里太常见。最终选赛车红·黑。

## 小尺寸检查

每次改动后看 16、32、48、128 四个 PNG，16 像素放在白底（浅色工具栏）和 `#202124`（深色工具栏）上：

1. 16 像素下还认得出 S 吗？
2. 白线至少 2 像素宽吗？
3. 红、黑两块在两种背景下还分得开吗？

## 如何修改

1. 改 `brand/icon.py` 里的常量（不要手改 `icon.svg`）。
2. 运行 `node brand/make-icons.mjs`。
3. 按上面的方法检查小尺寸。
4. `node skills/spr/setup.js` 重装，扩展会自动重新加载。
